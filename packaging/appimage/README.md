# The Linux AppImage

One file a Linux user downloads, makes executable and runs. Built by the
`linux` job in [`.github/workflows/release.yml`](../../.github/workflows/release.yml)
with the two scripts here.

```
AppDir/
  AppRun                      this folder's AppRun (picks the program)
  rondelek.desktop            this folder's, plus a copy in usr/share/applications
  rondelek.png                assets/icon/rondelek.png, plus usr/share/icons/…
  usr/bin/rondelek            the sampler app
  usr/bin/rondelek-game       the voice-game runner
  usr/share/doc/rondelek/     README.md, LICENSE
```

## Two binaries, one AppImage

The app starts a game by running `rondelek-game` from **its own folder**
(`App::spawn_game`, via `current_exe()`). Inside a running AppImage that
folder is the mounted `usr/bin/`, so the game is found with no special code.
The mount stays up while any process started from it runs, so a game keeps
working even if the app is closed first.

`AppRun` also lets the game run on its own, like double-clicking
`rondelek-game.exe` on Windows:

```bash
./rondelek-vX.Y.Z-x86_64.AppImage            # the app
./rondelek-vX.Y.Z-x86_64.AppImage --game     # the games; asks who's playing
```

A symlink named `rondelek-game` pointing at the AppImage does the same (the
runtime passes the invoked name in `$ARGV0`). The desktop entry offers it as a
"Voice games" action.

## Building one locally

```bash
cargo build --release
packaging/appimage/build.sh target/release v0.0.0-local dist
packaging/appimage/smoke.sh dist/rondelek-v0.0.0-local-x86_64.AppImage   # needs xvfb-run
```

A local build links against **your** glibc, so it may not start on older
distros. Release builds come from ubuntu-22.04 (glibc 2.35); to reproduce one,
run the same steps in an `ubuntu:22.04` container.

## What's bundled, and what isn't

No libraries. Directly linked are only glibc and `libasound.so.2` (ALSA, on
every desktop Linux). X11, Wayland, xkbcommon and GL are loaded at runtime by
winit/glutin and raylib's GLFW, and must come from the host: GL is the user's
graphics driver. The file picker uses the XDG desktop portal, not GTK.

That's also why `smoke.sh` draws real frames instead of checking `ldd`: a
missing runtime-loaded library only shows up when a window opens (it caught a
missing `libxkbcommon-x11` on a bare system).

The AppImage runtime is the static type2 runtime: it needs `fusermount3`
(fuse3, present on current distros), **not** the old `libfuse2`. Without FUSE,
`--appimage-extract-and-run` still works.

## Updates

The AppImage carries update information pointing at this repo's latest
release (`gh-releases-zsync|pipejesus|rondelek-twst-1|latest|…`), and each
release ships the matching `.zsync`. Tools like Gear Lever or AppImageUpdate
can then update it in place, downloading only the changed blocks.

## The icon

`assets/icon/rondelek.png`, generated by `cargo run --bin genicon`. It is
also the window icon of both programs.
