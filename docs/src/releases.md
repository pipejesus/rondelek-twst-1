# Releases & packaging

Releases are built by `.github/workflows/release.yml` when a `v*` tag is pushed.

| Job | Runner | Produces |
|---|---|---|
| `desktop` | `windows-latest` | `rondelek-<tag>-x86_64-pc-windows-msvc.zip` (both `.exe`s) |
| `linux` | `ubuntu-22.04` | `rondelek-<tag>-x86_64.AppImage` + `.zsync`, `rondelek-<tag>-x86_64-unknown-linux-gnu.tar.gz` |
| `publish` | `ubuntu-latest` | attaches every build job's files to the GitHub Release |

The build jobs only upload workflow artifacts; `publish` is the one job that
touches the release, so two jobs never race to create it. It runs on
`!cancelled()`, so a platform that failed doesn't stop the others shipping.
macOS legs are commented out in the matrix.

## Two binaries travel together

Every package holds both `rondelek` and `rondelek-game`, side by side. The app
starts a game by running the game binary from its own folder
(`App::spawn_game`, which uses `std::env::current_exe()`). See
[Architecture](architecture.md) for why the game is a separate process.

## The Linux AppImage

`packaging/appimage/` holds the AppImage pieces and its own README:

- `AppRun` runs the app by default, or the game on its own with `--game` (or
  when invoked through a symlink named `rondelek-game`).
- `rondelek.desktop` is the menu entry. `StartupWMClass=rondelek` matches the
  app's window id (`with_app_id("rondelek")` in `app/src/main.rs`).
- `build.sh` assembles the AppDir from two release binaries and runs
  appimagetool (static type2 runtime, zstd, with update information for
  zsync-based updates).
- `smoke.sh` runs the finished AppImage on a virtual display and checks that
  the app and the game each render a frame.

The job runs on ubuntu-22.04 because a binary needs at least the glibc it was
built against; 2.35 covers Ubuntu 22.04+, Debian 12+ and current rolling
distros. Nothing is bundled besides the two binaries: X11/Wayland/GL come from
the host at runtime.

## The icon

`assets/icon/rondelek.png` (512×512) is generated by `cargo run --bin genicon`
from the same pixel-art engine as the banner. Both binaries embed it as their
window icon, and the AppImage uses it as its icon.
